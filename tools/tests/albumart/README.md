# Artwork host regressions

From the repository root, in a clean checkout:

```sh
python3 tools/tests/albumart/run.py
```

Dependencies: Python 3 with Pillow (JPEG, PNG, GIF and WebP support), GCC with
AddressSanitizer and UndefinedBehaviorSanitizer, GNU make, SDL2 development files
and `sdl2-config`. The runner configures an ipod6g simulator to obtain its host
compile flags. It does not build or launch the simulator UI. No player, backup,
network access or private fixtures are required. Images, iTunesDB, ArtworkDB,
ithmb files and metadata frames are generated by the tests.

The default output is a new `albumart-tests-*` directory in the host temporary
directory. The runner prints that path. Keep output for review with:

```sh
python3 tools/tests/albumart/run.py --output /tmp/albumart-results
```

Use a new output directory for an independent run. Individual suites can be
rerun with `--only decode`, `--only resolver`, `--only metadata` or `--only flows`.
The resolver and metadata suites require objects from a prior decode run in the
same output directory. A normal full run supplies them automatically.

To compare the reviewed head with a fix, extract that head into a separate
source directory, then run the same tests against it:

```sh
mkdir /tmp/art-reviewed
git archive 5db0d99fdce8d674371183642c4af71e03e3fafc | tar -x -C /tmp/art-reviewed
python3 tools/tests/albumart/run.py --source-root /tmp/art-reviewed \
    --output /tmp/art-reviewed-results
```

The R1–R8 assertions fail on that head. The test adapters account for the old
resolver signature and the absence of typed requests. They do not replace the
production functions under test. Each executed command and its output has a
separate log in the output directory. Sanitizer failures stop the test; the
runner does not disable leak detection or recover from undefined behavior.

## Coverage

- `decode.py`: complete image/stream modules; generated JPEG, PNG, BMP, GIF and
  WebP images; EXIF orientations 1–8 with dimension and quadrant-pixel checks;
  small-buffer rejection and embedded-stream offsets. Lossless WebP rejection
  is an expected limitation. Metadata helpers linked only for stream support
  are not instrumented in this suite.
- `resolver.py`: complete resolver, source revision, iTunes adapter and decoder
  modules. Checks all four album-cache policies, explicit playback preferences,
  direct artist-directory resolution and a valid 56px iTunes thumbnail followed
  by missing and short larger candidates. Decoded pixels are checked.
- `metadata.py`: production ID3, MP4, FLAC and Vorbis frame parsing with generated
  front-cover fixtures. Those parsers and the image modules use ASan/UBSan.
  The bitmap-reference lifetime test extracts production functions and supplies
  a deterministic handle table.
- `flows.py`: extracted production playback, registry, reference, request,
  offer, candidate-loop, book-folder and book-repair functions. POSIX registry
  and reference I/O is real. Queue delivery, storage state, core allocation,
  candidate decoding and book-index iteration use deterministic adapters.

| Finding | Regression assertion |
| --- | --- |
| R1 | A publication reaches prefetched B while A is current; artist and Auto dependencies invalidate; missing slots retry after generation changes. |
| R2 | Persisted artist repair keeps its directory role; book repair selects the indexed path and retains ZIP member offsets and lengths. |
| R3 | Playback forwards its preference; the complete resolver obeys all four policies; changing the source setting invalidates old references. |
| R4 | ENOSPC opening a reference sets the request I/O failure and leaves no published reference. |
| R5 | A sleeping track-change callback opens no files; the offer survives sleep, resumes after wake, and retries scratch shortages at most three times. |
| R6 | Flat and nested book callers pass directories; the resolver chooses the author's portrait rather than the parent picture. |
| R7 | Rejected larger iTunes candidates preserve the accepted filename, geometry, range and decoded red pixels. |
| R8 | After ENOSPC recovery, the next offer tries the valid second candidate and publishes its reference. |

These are host tests. They do not establish device playback, audio timing,
physical disk wake behavior, USB IRQ scheduling, stack high-water use or
power-loss recovery. The queue adapter does not run the firmware scheduler.

## DEVICE-BUGS-1 coverage

The resolver also checks three format-9-to-10 source losses: files-only with
embedded-only art, files-only with iTunes-only art, and embedded-only with
file-only art. Fallback policies retain all three. Directory tests distinguish
a direct artist portrait from an ancestor picture and retain the album's
parent-folder fallback. Registry tests check an initially empty v10 namespace,
policy invalidation, and failure to persist a typed request on ENOSPC.

For an isolated format-9 source comparison, generate decoder objects first,
then select just the comparison cases (existing R1-R8 checks intentionally
reject that older implementation):

```sh
python3 tools/tests/albumart/run.py --source-root /tmp/art-v9 \
    --output /tmp/art-v9-results --only decode
ART_RESOLVER_CASES='DEVICE-policy DEVICE-directory' \
    python3 tools/tests/albumart/run.py --source-root /tmp/art-v9 \
    --output /tmp/art-v9-results --only resolver
```

Adjacent UI checks run with `python3 tools/tests/device_ui_test.py`. They execute
the production list action wrapper and charging monitor with deterministic
adapters, and check Scrim's battery/busy viewport separation. They do not draw
the theme on a display.

`tools/tests/arm_skin_stack.py --build <ARM-build> --elf <rockbox.elf>` executes
the ELF's renderer instructions using Unicorn and reads ABI offsets using that
build's compiler. Install `unicorn` and `pyelftools` in a separate environment.
The default 52-conditional fixture exceeds the old 8 KiB stack budget and fits
after keeping drawing scratch out of the recursive frame. The evaluator is an
adapter; this stress case does not reconstruct the reported device action.
